# Руководство по Проверке Тестов

## 1. Задача, которую решают тесты

Тесты в данном проекте предназначены для автоматизированной верификации корректности работы алгоритмов поиска Эйлерова пути (Хиерхольцера и Флёри), а также для проверки надежности пользовательского интерфейса и обработки данных. 

Основные цели тестирования:
- **Корректность алгоритмов**: Убедиться, что для валидных графов (эйлеровых циклов или путей) алгоритмы возвращают правильную последовательность вершин.
- **Обработка ошибок**: Проверить, что программа корректно реагирует на невалидные входные данные (разрывные графы, графы с неверным количеством нечетных вершин).
- **Граничные условия**: Удостовериться в работе программы на пустых графах, графах из одной вершины или одного ребра.
- **Структурное покрытие**: Гарантировать, что все строки и ветви кода были выполнены хотя бы один раз (Statement и Branch coverage).

## 2. Что было реализовано в тестах

В рамках проекта был реализован комплексный набор тестов, включающий:

1.  **Модульные тесты (Unit Tests)**:
    -   `test_hierholzer.py`: Проверяет алгоритм Хиерхольцера на различных топологиях (циклы, пути, несвязные графы).
    -   `test_fleury.py`: Проверяет алгоритм Флёри, включая специфическую логику обнаружения мостов.
    -   `test_graph_utils.py`: Тестирует валидацию графов и проверку условий существования Эйлерова пути.
    -   `test_io_handler.py` и `test_console_input.py`: Проверяют ввод/вывод данных и обработку JSON.

2.  **Техники тест-дизайна**:
    -   **Boundary Value Analysis (BVA)** (`test_bva.py`): Тесты на граничных значениях (0, 1, 2 вершины; пустые списки).
    -   **Equivalence Partitioning (EP)** (`test_equivalence.py`): Разделение входных данных на классы эквивалентности (валидные/невалидные типы, структуры).
    -   **Statement Testing** (`test_statement.py`): Обеспечение 100% покрытия строк кода.
    -   **Branch Testing** (`test_branch.py`): Проверка прохождения всех ветвей условий (`if/else`).

3.  **Мутационное тестирование**: Проведена проверка качества самих тестов с использованием `MutPy` (результаты в `mutation_report.md`).

## 3. Как запустить тесты и приложение (консольные команды)

Все команды выполняются из **корневой директории проекта** (`lab1`).

### 3.1. Запуск всех тестов

Для запуска полного набора тестов выполните:

```powershell
python -m pytest tests/ -v
```

### 3.2. Запуск одного файла тестов

Чтобы запустить только один конкретный файл с тестами (например, тесты граничных значений BVA):

```powershell
python -m pytest tests/test_bva.py -v
```

Вы можете заменить `tests/test_bva.py` на любой другой файл из папки `tests/` (например, `tests/test_fleury.py`).

### 3.3. Запуск мутационного тестирования (Python 3.9)

Для корректной работы мутационных тестов необходимо:
1.  **Исключить модуль `src.main`** (чтобы избежать зависания на `input()`).
2.  **Указать раннер `pytest`** (так как тесты написаны в стиле Pytest).

Используйте эту точную команду:

**Вариант 1 (Краткий отчет):**

```powershell
py -3.9 run_mut.py --target src.graph_utils src.hierholzer src.fleury src.io_handler src.console_input --unit-test tests --runner pytest
```

**Вариант 2 (Детальный отчет):**

```powershell
py -3.9 run_mut.py --target src.graph_utils src.hierholzer src.fleury src.io_handler src.console_input --unit-test tests --runner pytest -m
```

### 3.4. Запуск самого консольного приложения

Для запуска основного приложения используйте команду:

```powershell
python -m src.main
```

> **Важно:** Не запускайте файлы напрямую (например, `python src/fleury.py`), так как это вызовет ошибку импорта модулей (`ModuleNotFoundError`). Всегда используйте флаг `-m` и запускайте из корня проекта.

## 5. Итог (пояснение)

**Что означает вывод тестов:**

1.  **Зеленый статус (PASSED)** всех тестов означает, что реализация алгоритмов соответствует требованиям технического задания. Алгоритмы Хиерхольцера и Флёри корректно находят Эйлеровы пути и циклы на проверенных наборах данных.
2.  **Отсутствие ошибок (Failed/Errors)** подтверждает, что программа стабильна и корректно обрабатывает исключительные ситуации (например, попытку найти путь в несвязном графе).
3.  **Покрытие кода**, если оно проверялось, показывает, что нет "мертвых зон" в коде, которые не были бы затронуты тестами.

**Что получилось реализовать:**
Удалось создать надежное, протестированное консольное приложение, которое не только решает математическую задачу графов, но и обладает устойчивым интерфейсом и проверено с использованием продвинутых тестировочных методологий (TDD, BVA, EP).
