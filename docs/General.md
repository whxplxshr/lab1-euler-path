Подробное описание всего контекста задачи, назначения и инструментов разработки
1. Введение

Вы работаете над разработкой консольного приложения для решения задачи поиска Эйлерова пути в неориентированном графе. В рамках задания предполагается использование двух различных алгоритмов для решения этой задачи: Алгоритм Хиерхольцера и Алгоритм Флёри. Важно, что алгоритмы должны быть реализованы в одном проекте, с возможностью выбора одного из них пользователем.

Алгоритмы должны быть реализованы на языке Python, с использованием библиотеки для работы с графами, такой как networkx. Графы будут загружаться пользователем через файл в формате JSON, а результаты работы приложения (то есть найденный Эйлеров путь) должны выводиться как в консоль, так и сохраняться в файл.

Проект требует соблюдения принципов TDD (разработка через тестирование) и тестирования через несколько техник проектирования тестов.

2. Основная задача

Ваша задача заключается в создании приложения, которое будет:

Реализовывать два алгоритма для поиска Эйлерова пути:

Алгоритм Хиерхольцера: использует обход в глубину для поиска пути.

Алгоритм Флёри: применяет пошаговое использование рёбер.

Разработать пользовательский интерфейс для:

Ввода данных (графа), который можно либо ввести вручную, либо загрузить через JSON-файл.

Вывода результата в консоль и в файл.

Обработки ошибок (например, если путь не найден).

Разработать систему модульных тестов, включая позитивные и негативные сценарии.

Применить мутационное тестирование для оценки качества тестов.

Применить различные методы проектирования тестов, такие как Boundary Value Analysis, Equivalence Partitioning, Statement Testing, и Branch Testing.

3. Требования к функционалу:

Ввод и вывод данных:

Приложение должно поддерживать два типа ввода:

Ввод данных вручную (например, пользователю предлагается ввести количество рёбер и вершин).

Загрузка данных через JSON-файл. Графы должны быть в стандартном формате JSON, в котором указаны вершины и рёбра.

Приложение должно обрабатывать файлы произвольного размера и корректно работать с ними, даже если граф слишком большой.

После выполнения алгоритма, результаты должны быть выведены как в консоль, так и сохранены в файл (желательно в формате JSON).

Процесс разработки:

Приложение должно быть разработано по принципам TDD (Test-Driven Development), что означает, что тесты должны быть написаны до реализации основной функциональности.

Для тестирования должен быть использован фреймворк PyTest.

Использование мутационного тестирования (например, Pitest или MutPy) для оценки качества тестов.

Проектирование тестов:

Для тестирования необходимо использовать различные техники проектирования тестов:

Boundary Value Analysis (анализ граничных значений) — для проверки на крайних значениях (например, пустой граф или граф с минимальными рёбрами).

Equivalence Partitioning (разбиение на эквивалентные классы) — для классификации входных данных на классы с одинаковым поведением.

Statement Testing (тестирование операторов) — для обеспечения того, чтобы все операторы в программе были проверены.

Branch Testing (тестирование ветвей) — для проверки всех возможных путей выполнения программы.

Мутационное тестирование:

После написания тестов необходимо проверить их эффективность с помощью мутационного тестирования.

Программа должна быть проверена на мутационные операторы (например, изменение знаков, удаление или добавление частей кода).

Метрики мутационного тестирования, такие как LCC, MCC, CoveredCodeMSI, должны быть рассчитаны и проанализированы.

4. Инструменты и технологии:

Язык программирования: Python.

Библиотеки:

networkx — для работы с графами (создание графа, поиск рёбер, обход графа).

json — для загрузки и сохранения данных в формате JSON.

PyTest — для написания модульных тестов.

MutPy или Pitest — для мутационного тестирования.

Методы тестирования:

Boundary Value Analysis.

Equivalence Partitioning.

Statement Testing.

Branch Testing.
